# Контрольный захват: Kabal Fatality 1

## Запись

`capture-20260725-111821`: Kabal (`0A`) против Scorpion (`12`), победа 2:0,
завершение Kabal Fatality 1. Захвачено 6405 кадров за 115,266 секунды с
интервалом 18 мс. Полный поток RAM и журнал относятся к одному процессу MAME
(`PID 24660`) и одному адресу основной RAM (`0x18F73038`).

## Фазы раундов и FINISH HIM

Кандидат `0x0C454` повторил осмысленную последовательность:

- кадр `1942`: `00 -> 01` после окончания первого раунда;
- кадр `2336`: `01 -> 00` с началом второго раунда;
- кадр `3367`: `00 -> 03` после финального нокаута, когда игра перешла в
  `FINISH HIM`;
- кадр `5740`: `03 -> 01` после завершения Fatality.

Это уточняет назначение значений: `01` сопровождает обычный промежуток между
раундами, а `03` — финальную фазу, в которой разрешён добивающий приём.

## Сторона бойца и точный ввод

В `moves.js` Kabal Fatality 1 записан как `↓, ↓, ←, →, BL`. Перед успешной
попыткой координаты объектов были:

- Kabal: X `546`;
- Scorpion: X `406`.

Значит, Kabal находился справа от соперника и смотрел влево. Физический ввод из
RAM на кадрах `5476..5511`:

1. `DOWN` — кадр `5476`;
2. `DOWN` — кадр `5488`;
3. `RIGHT` — кадр `5497`;
4. `LEFT` — кадр `5508`;
5. `BL` — кадр `5511`.

После нормализации LEFT/RIGHT относительно стороны бойца получается ровно
`DOWN, DOWN, LEFT, RIGHT, BL`, то есть комбинация книги. Это доказывает, что
будущий распознаватель конкретного приёма должен сравнивать не абсолютные
LEFT/RIGHT, а направления после нормализации по координатам бойцов.

Указатели объектов обнаружены в `0x0C13A` (P1) и `0x0C2B0` (P2). Они хранят
TMS34010 bit-address; адрес объекта в снимке RAM вычисляется как
`(pointer - 0x01000000) / 8`. Координата X находится по смещению `+0x12`, Y —
по `+0x16`, флаги объекта — по `+0x2C`, ID бойца — по `+0x3E`.

## Подтверждение успешного добивания

На кадре `5512`, сразу после последнего `BL`, синхронно изменились:

- `0x0C426`: `00 -> 01`;
- `0x0C442`: `00 -> 01`;
- `0x0C4E6`: `00 -> 01`.

На всех более ранних попытках в той же фазе `FINISH HIM` эти поля оставались
нулевыми. Тот же тройной переход ранее был найден у Kano Fatality 2. Теперь он
независимо подтверждён другим бойцом, другой комбинацией и Fatality с
направлениями.

## Вывод

Для Fatality уже есть полный проверяемый набор сигналов:

1. активный матч и точные бойцы;
2. финальный нокаут и фаза `FINISH HIM` (`0x0C454 == 03`);
3. покадровый ввод;
4. сторона бойца и нормализованная комбинация;
5. отдельное подтверждение успеха тройным переходом флагов.

Этого достаточно, чтобы надёжно отличать удачное конкретное Fatality от
неверной попытки и от обычной победы. Следующий контроль нужен уже для другого
типа завершения матча, чтобы определить, являются ли три флага общими для всех
finishing moves или только для Fatality.
