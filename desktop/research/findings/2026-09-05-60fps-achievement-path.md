# UMK3 60 FPS: ROM-семантика и путь достижения, Test 18

Обновление 7 сентября: Test 18 вручную проверен. Team Edition 60 FPS принят
сервером; UK 60 FPS блокируется из-за отсутствующего каталога читов.
Исправление и свежие доказательства: [Test 19](2026-09-07-empty-cheat-catalog.md).
Ниже сохранены результаты подготовки Test 18 до ручного прогона.

## Проверенные данные

- Сравнены все 30 распакованных файлов в каждой паре umk3tm/umk3tm60 и
  umk3uk/umk3uk2. Внутри каждой пары файлы побайтово одинаковы.
- Сравнение сделано и для runtimes/mame-0.129/roms, и для реально использованного
  в отчёте E:/games/MAME/MAME 0.129/roms. Между этими двумя установками отличаются
  программные um312u54.bin и um312u63.bin. Поэтому архивный SHA256 сам по себе
  не доказывает тождество программ, и установки нельзя смешивать.
- Полные SHA256 архивов и каждого распакованного файла:
  work/umk3-60fps-20260905/rom-evidence.json.
- Источник воспроизведения: Test 17, diagnostics/
  mame-fight-report-20260829-155802-P17132.csv, ROM umk3tm60.
  12 407 сэмплов с игровыми данными, два обнаруженных адреса RAM:
  0x1B910038 и 0x17535038. Интервал опроса: медиана 251 мс, p95 257 мс,
  максимум 272 мс. Это интервалы моста, а не измерение FPS игры.
- Повторное воспроизведение с текущими MameBridge, FightTracker, ModeTracker,
  CpuCheatPolicy и атрибуцией даёт 23 допущенных завершённых CPU-матча и один
  отклонённый матч с читом. События допустимых матчей проходят правило outbox.
  Это доказательство локального допуска, а не отправки в реальный профиль.
- Обезличенная fixture: desktop/tests/fixtures/umk3tm60-cpu-test17.csv.
  Она содержит числовые игровые поля и состояния чит-монитора, без пути
  процесса, имени профиля и текста отчёта. Пустые tower_id/tower_fight_number
  в исходном CSV означают отсутствие контекста башни, а не адрес памяти.
- Локальный -listxml umk3tm60 сообщает midwunit.c, TMS34010 50 MHz и refresh
  54.815170 даже для названия 60fps. Это метаданные драйвера; они не измеряют
  фактический темп игры. Runtime-патчи драйвера из этого вывода не восстановить.

## Память и тайминги

Карта памяти и частота опроса в этой задаче не изменялись. Рабочие поля:
P1 character/health/rounds 0x0C146/0x0C14C/0x0C152;
P2 0x0C2BC/0x0C2C2/0x0C2C8; finish phase 0x0C454;
power bars 0x0C424; tower states 0x0C5D7/0x0C5D9.

В реальном tm60-потоке присутствуют штатные значения фаз 0, 1, 2, 3 и
счёта 0, 1, 2. Подтверждённые результаты 1/2 детектируются. Фаза 3 сама
по себе не считается результатом: сохранено ожидание 1/2. Тесты проверяют
один увиденный сэмпл результата, повторные сэмплы без дубликатов, присоединение
посреди матча и следующий полный матч. Непроверенные адреса не добавлялись.

Свежего полного захвата umk3uk2 и новой сессии отказа CPU пока нет.
Перенос семейной семантики UK основан на одинаковом программном ROM;
это не подменяет ручную проверку UK 60 FPS.

## Аудит точных сравнений ROM

- MameBridge.DetectRomId: четыре ID уже распознавались; whitelist desktop/server
  также уже включал все четыре. Они не являются найденным исправлением.
- MameTeamLayoutTracker.Observe и MameTeamPlayerAttribution.TryResolveActiveSide:
  Team Edition теперь включает umk3tm60. По данным ROM наследует семейную
  семантику. Это только диагностика активного/ожидающего игрока; запрет
  достижений для online 3–6 и команд 2×2/3×3 сохранён.
- MameFinisherTracker.IsAntifatality: UK 60 FPS наследует охраняемый переход
  Kabal 0x12 -> 0x22 при фазе 3, нулевых стандартных флагах добивания и
  подтверждённом победителе. Team Edition по-прежнему исключён.
- server achievement_rules.py и web/data/achievements.js: то же условие UK
  включает umk3uk2. Серверное изменение только локальное, не развёрнуто.
- MameFightTracker, MameAchievementAttribution и MoveBookHost не имели
  исключающей все достижения ветки только для базовых ID.

## Почему нужен новый захват

В старом CSV нет сведений о состоянии входа, постановке конкретного события
в очередь и принятом серверном ответе. Он не объясняет отсутствие награды
при уже допущенных локальных событиях. В Test 18 --diagnostics пишет также
diagnostics/achievement-path-*.jsonl:

- observed: ROM, режим, матч/сессия/последовательности, состояние допуска;
- consumed-without-queue: событие окончательно пропущено с причиной;
- restored / restore-discarded: результат чтения очереди;
- queued: persisted либо memory-only;
- submit-started, send-discarded, submit-error: отправка или её отказ;
- server-response: accepted, новые награды и серверные счётчики.

API origin записывается без логина, пароля и query-параметров. Токены,
HTTP-заголовки, тела ответов и сообщения исключений не записываются.
Неизменившиеся наблюдения не размножают журнал. Без --diagnostics файла нет.
