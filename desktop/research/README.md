# Исследовательский захват памяти UMK3

Инструмент нужен для поиска устойчивых игровых сигналов, которых пока нет в
диагностическом мосте MK3 MoveBook: вводов игроков, состояния `FINISH HIM`,
успешного типа добивания, конкретного Fatality, Brutality и других приёмов.

## Что он делает

- открывает процесс MAME только с правами чтения;
- примерно раз в игровой кадр читает все 512 КБ основной RAM UMK3;
- сохраняет первый полный снимок и дальнейшие изменившиеся участки;
- параллельно ведёт `known-fields.csv` с уже известными полями;
- не нажимает кнопки, не меняет RAM и не модифицирует ROM.

Каждый запуск создаёт отдельную папку
`research-captures/capture-YYYYMMDD-HHmmss` рядом с EXE.

## Сборка

```powershell
powershell -ExecutionPolicy Bypass -File .\build-research.ps1
```

Готовый файл появится в `build/MK3 Memory Capture.exe`.

## Контрольная запись

1. Запустить `MK3 Memory Capture.exe`.
2. Запустить MAME и нужный ROM.
3. Провести один заранее оговорённый бой.
4. После результата нажать `Ctrl+C` в окне рекордера и дождаться строки
   `Захват завершён`.
5. Передать всю созданную папку захвата без переименования её файлов.

Для автоматической остановки можно использовать параметр `--seconds N`.

Для первого сравнения нужны две отдельные записи с одинаковыми бойцами:

- обычная победа без добивания;
- победа с одним заранее названным Fatality.

После них отдельными записями проверяются второй Fatality, Babality,
Friendship, Animality и Brutality. Такой порядок позволяет отличить общий
флаг завершения матча от идентификатора конкретного добивания.

## Расшифровка

`analyze_capture.py` преобразует бинарный поток в таблицу активности кадров и
рейтинг изменявшихся адресов:

```powershell
python .\analyze_capture.py <папка-захвата>
```

Результат создаётся в подпапке `analysis`. Скрипт является инструментом
разработчика и не входит в пользовательскую сборку MK3 MoveBook.

Помимо общей активности, анализатор создаёт:

- `input-events.csv` — нажатия обоих игроков, сторона бойца и направления,
  нормализованные так, как будто боец смотрит вправо;
- `player-state.csv` — указатели игровых объектов, координаты X/Y, флаги объекта,
  ID бойца внутри объекта и текущая сторона каждого игрока.
- `finisher-events.csv` — только подтверждённые добивания: код типа, общий флаг
  успеха, победившая сторона и недавняя нормализованная комбинация. Сейчас
  подтверждены коды `01` для Fatality и `05` для Babality.

Нормализация нужна для сравнения с `moves.js`: когда боец находится справа от
соперника и смотрит влево, физические LEFT/RIGHT меняются местами, а запись
приёма в книге остаётся заданной для исходного положения лицом вправо.
