# Синхронизация достижений

Portable-клиент отправляет нормализованные события MAME только после входа
через Discord. Правила достижений выполняются на сервере; JavaScript-интерфейс
лишь отображает полученный серверный снимок.

## API

- `GET /api/v1/achievements/me` возвращает статистику и разблокировки текущего
  пользователя.
- `POST /api/v1/achievements/events` принимает одно событие MAME и возвращает
  обновлённый снимок прогресса.
- Оба endpoint требуют access JWT в заголовке `Authorization: Bearer ...`.
- События дедуплицируются по `(user_id, source, event_key)`, поэтому повторная
  отправка не увеличивает статистику второй раз.

Поддерживаются события `round-ended`, `match-ended`, `finisher` и `special`.
Сервер хранит
исходный payload события, время и статус проверки `unverified-local`. Desktop
добавляет `match_scope=computer` для башни или `match_scope=online` для
подтверждённой Kaillera. У завершения башни дополнительно передаются `tower_id`
из диапазона `0..3` и `tower_completed=true`.

Каждое учитываемое событие также содержит `match_fully_observed=true`.
Для online обязательны `netplay_total_players=2` и `team_size=1`; для CPU число
сетевых участников и размер online-команды равны нулю. Сервер fail-closed
проверяет эти поля и ROM (`umk3tm`, `umk3tm60`, `umk3uk`, `umk3uk2`). События
старого клиента без этих доказательств остаются только
идемпотентными no-op и не меняют профиль.

Событие без продуктового `match_scope` сервер сохраняет для идемпотентного
опустошения старого outbox, но не учитывает в статистике и не использует для
выдачи достижений. Поэтому локальные Versus-события из временных тестовых сборок
не переносятся в рабочий профиль.

Для `match_scope=computer` сервер учитывает событие только при
`cheat_policy_state=disabled`. Desktop выставляет это значение после проверки
живого списка читов MAME: простое значение `cheat 1` разрешает подсистему и само
по себе не является нарушением. Состояния `unknown` и `enabled` сохраняются для
идемпотентного опустошения очереди, но не меняют CPU-статистику и достижения.
Для `match_scope=online` поле намеренно не влияет на прогресс.

Категории «Противостояния» и «Особые испытания» сервер полностью блокирует до
получения всех четырнадцати выбранных боевых дебютов Mortal Kombat 3, включая
Robot Smoke, но без Sheeva и Shao Kahn. Заблокированные события не увеличивают
даже скрытые счётчики. Событие последнего дебюта лишь открывает категории: прежние
условия не пересчитываются, а проверка начинается со следующего нового события.

События одного боя получают общий `reward_group_key`. Статистика обрабатывается
для каждого события как обычно, но новая разблокировка в пределах группы может
быть только одна. Так дебют, сюжетная победа, рубеж побед, особое действие и
добивание не выдаются пачкой за один матч. Редкий `Toasty!` отправляется раньше
завершения 42%-комбо Шивы и поэтому имеет приоритет, если они совпали.

## Текущая модель игрока

Серверный контракт всегда представляет авторизованный профиль стороной P1:

- завершённый матч увеличивает `matches_played` независимо от победителя;
- `computer_matches_played`/`computer_victories` и
  `online_matches_played`/`online_victories` ведутся раздельно;
- победа, дебют бойца и сюжетное противостояние засчитываются только при победе
  P1;
- подтверждённая победа над Shao Kahn с ID `0x19` открывает одно из четырёх
  достижений согласно `tower_id`;
- Flawless Victory засчитывается только для P1;
- добивания P2 или CPU не засчитываются профилю.
- зависимости проверяются только по достижениям, полученным до текущего
  события: Соня → «Старые счёты», Kabal → «Порвать с Black Dragon», Liu Kang →
  «Защитник Земли»; Friendship Stryker требует его дебют и «Мирный исход»;
- `round-ended` передаёт номер раунда, счёт и запомненное состояние Danger;
  `special` передаёт подтверждённые сигналы Frosty, Toasty, 42%-комбо Шивы,
  апперкота в Finish Him и перехода между аренами.

Сервер не определяет локальное место Kaillera. Desktop-клиент применяет перед
отправкой консервативную политику:

- подтверждённая башня против CPU на стороне P1 отправляется без преобразования;
- если локальный P2 выиграл вызов и продолжил башню против CPU, клиент меняет
  стороны так же, как для сетевого P2;
- в подтверждённой Kaillera с известным layout и ровно двумя реальными
  участниками и одним бойцом на сторону локальный P1 отправляется без
  преобразования;
- для локального P2 клиент меняет стороны победителя, бойцов, здоровья, счёта,
  Danger, победителя финишера и автора особого события, поэтому владелец профиля
  снова представлен как P1;
- Team Edition с тремя-шестью участниками продолжает диагностически определять
  локальный слот, активного бойца и ожидание, но политика достижений полностью
  блокирует такие события;
- при двух участниках Kaillera выбор команд 2×2 или 3×3 также блокируется;
- локальный Versus, неизвестный режим, неизвестный layout, наблюдатель,
  неподдерживаемый ROM, любое число участников кроме двух и размер команды кроме
  одного бойца не создают серверных событий и не попадают в offline-outbox.

Desktop повторяет только политику допуска режима, чтобы запрещённые события не
попадали в offline-outbox. Prerequisites и открытие категорий всегда решает
backend по уже сохранённому профилю; клиент не выдаёт достижения локально.

Старые события не содержат контекст режима, поэтому миграция не распределяет
их между CPU и онлайном наугад. Общие `victories` и `matches_played` сохраняются,
а API возвращает их нераспределённую часть в `unclassified_victories` и
`unclassified_matches_played`. Новые события увеличивают общий и ровно один
режимный счётчик одновременно.

Схемы `1×2`, `2×1`, `2×2`, `2×3` и `3×3` видны в диагностике (`MAP`, `SLOT`,
активный участник), но в текущем релизе не учитываются.

## Поведение клиента

- Без входа каталог достижений доступен только для просмотра; события не
  создаются и прогресс не показывается.
- После входа клиент загружает серверный снимок и начинает захват новых событий.
- Если память впервые подключена уже во время боя, клиент показывает
  «Синхронизация с текущим матчем», не создаёт для него событий и начинает
  прогресс с первого раунда следующего матча после сброса игровых счётчиков.
- Событие, уже видимое в MAME в момент входа, помечается как исходное и не
  отправляется задним числом.
- Перед отправкой каждое событие атомарно сохраняется в локальный outbox,
  зашифрованный Windows DPAPI для текущего пользователя. Outbox разделён по
  адресу API и внутреннему `user_id`, поэтому события разных серверов и профилей
  не смешиваются.
- При временной ошибке сети события остаются в outbox и могут быть повторно
  отправлены кнопкой в интерфейсе. После перезапуска Portable-клиент загружает
  очередь текущего профиля и автоматически отправляет её после восстановления
  серверной сессии.
- Подтверждённое сервером событие удаляется из outbox. Если клиент аварийно
  завершится между ответом сервера и локальным удалением, повтор безопасен:
  сервер дедуплицирует событие по `(user_id, source, event_key)`.
- Явный выход очищает ключи и очередь в памяти, но оставляет неподтверждённые
  события на диске за прежним профилем. Они восстановятся только после входа в
  тот же профиль и никогда не будут отправлены от имени другого пользователя.
- Старый локальный прогресс версии `v2` автоматически не импортируется. Новый
  кэш `v4` содержит только последний полученный серверный снимок и не является
  источником истины.

## Локальная проверка

1. Применить миграции и запустить сервер на `127.0.0.1:8010`.
2. Запустить отдельную тестовую Portable-сборку.
3. Войти через Discord и открыть достижения: индикатор должен перейти в
   состояние «Прогресс синхронизирован».
4. Выиграть башенный матч против CPU: общие и `computer_*` счётчики должны
   увеличиться только после ответа сервера, а `online_*` остаться прежними.
5. Победить Shao Kahn в одной башне: должно открыться достижение именно её
   `tower_id`; для остальных трёх ID достаточно серверных автоматических тестов.
6. В Kaillera с двумя участниками и одним бойцом на сторону проверить локальные
   P1 и P2: победы и поражения должны относиться к владельцу профиля после
   P1-нормализации.
7. При двух участниках выбрать команды 2×2 и 3×3: профиль и offline-outbox не
   должны изменяться.
8. В Team Edition проверить 3–6 участников: профиль и offline-outbox не должны
   изменяться, а командная диагностика должна продолжать работать.
9. Проверить локальный Versus, неизвестный layout и запуск во втором раунде:
   серверные события создаваться не должны; после синхронизации учитывается
   следующий полный матч.
10. Закрыть и снова открыть клиент: серверный прогресс должен восстановиться.
11. Выполнить явный выход: прогресс должен скрыться, а новые события перестать
   учитываться.
12. После входа отключить сеть, завершить допустимый матч и убедиться, что
   интерфейс сообщает о сохранённом на компьютере событии.
13. Закрыть Portable, восстановить сеть и запустить его снова: очередь должна
   восстановиться, событие — появиться на сервере ровно один раз, а локальный
   outbox — очиститься после подтверждения.
14. До четырнадцати дебютов выполнить условия закрытых категорий и убедиться,
   что нет разблокировок и скрытого счётчика финишеров. Последний дебют только
   открывает категории; те же условия должны сработать лишь при новых событиях.
